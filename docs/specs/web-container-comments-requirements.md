# 网页托管增强容器与评论能力需求

状态：已实现，已通过 Pi 隔离环境验收，待合并

更新时间：2026-09-16

面向读者：产品、前后端开发、测试、网页生成 Agent

## 1. 背景与目标

网页托管需要从“静态文件直出”扩展为统一页面容器。容器提供固定导航、登录状态和评论入口，同时必须保留托管网页原有的按钮、表单、地图、图表、播放器等交互。

本能力解决四个问题：

1. 访问者能确认当前登录态，并返回系统主页或网页托管页。
2. 已登录且有页面访问权的用户能对整页、文字、图片和组件发起讨论。
3. 评论形成可追溯消息流，支持回复、解决、重开和重新关联。
4. 页面重新发布后，仍存在的内容继续显示评论；无法定位的未解决评论集中在页尾提示。

## 2. 核心判断

【核心判断】

✅ 值得做：托管网页本来就是评审和协作产物，评论应由宿主统一提供，避免每个 HTML 重复实现账号、权限、存储和升级逻辑。

【关键洞察】

- 数据结构：主题保存“当前定位”和“原始定位”，事件表保存完整消息与状态历史；两张表即可覆盖追踪、重开和迁移，不需要额外绑定表。
- 复杂度：评论开关是标签页内的界面状态；项目可见范围和应用 scope 继续由服务端权限模型决定。
- 风险点：最大风险是容器拦截原网页事件，尤其是地图手势；因此评论标记不接收指针事件，交互模块只能从侧栏选择。

【Linus 式方案】

1. 用 `container_mode` 明确区分增强容器与原始页面。
2. 用稳定页面/模块 ID 和原文上下文定位，定位失败就保守降级，不猜目标。
3. 用主题 + 事件两张表保存当前状态和不可变历史。
4. 旧项目迁移后保持 `raw`，不改变已有页面行为。

## 3. 用户与权限

| 角色 | 页面可见条件 | 查看评论 | 创建/回复 | 解决、重开、重新关联 |
| --- | --- | --- | --- | --- |
| 未登录用户 | 仅公开项目 | 不允许，且不显示入口 | 不允许 | 不允许 |
| 已登录普通用户 | 满足项目 `private/members/authenticated/public` 规则 | 允许 | 允许 | 仅自己创建的主题 |
| 项目所有者 | 项目归属自己 | 允许；项目停用后仍可查历史 | 项目启用且为增强模式时允许 | 项目内任意主题 |
| AK/SK 应用 | 所属用户有页面访问权，且 Token 有对应 scope | `web-comments:read` | `web-comments:write` | 遵循所属用户规则 |

权限要求：

- 匿名用户访问公开页面时只得到浏览菜单，不请求评论列表，不暴露评论 CSRF 凭据。
- 未登录不可见、当前用户不可见、项目不存在、项目已下线和审核不可用，对页面访问统一返回真实 HTML 404。
- 私有项目的评论 API 不向无权访问者泄露项目是否存在。
- 浏览器评论写请求使用仅限 `web-comments` 的 CSRF Token；托管页不能取得账号级 CSRF Token。
- `web-projects:write` 不自动授予评论权限；应用必须显式申请 `web-comments:read/write`。

## 4. 页面容器

### 4.1 容器模式

| 模式 | 行为 |
| --- | --- |
| `enhanced` | 对 HTML/HTM 响应注入平台运行时，显示固定菜单，并提供评论模式。静态文件本身不被改写。 |
| `raw` | 原样返回所有文件，不注入菜单，不允许新增评论；已有评论数据保留。 |

新建项目默认 `enhanced`。执行数据库迁移时，已有项目默认 `raw`，由所有者明确切换后才启用容器。

### 4.2 固定菜单

菜单固定在页面顶部，使用 Shadow DOM 隔离样式，包含：

- 当前项目名称与登录显示名；未登录显示“未登录”。
- “系统主页”链接 `/`。
- “网页托管”链接 `/web-share`。
- 已登录且可评论时显示“评论”按钮；进入评论后可“返回浏览”。

刷新、新标签页、账号切换和页面逻辑路由变化后均回到浏览状态。浏览状态不加载评论正文、不监听文字选区，保留网页原有交互。

## 5. 评论交互

### 5.1 可评论对象

| 对象 | 创建方式 | 定位信息 |
| --- | --- | --- |
| 整页 | 侧栏“评论整页” | 稳定 page ID；没有时使用项目相对路径 |
| 文字 | 用户使用浏览器原生选区后点击“评论所选文字” | target ID、原文、前后文、page ID |
| 图片 | 从侧栏的可评论目标列表选择 | 稳定 target ID 和标签 |
| 组件/模块 | 从侧栏的可评论目标列表选择 | 稳定 target ID 和标签 |

正文最多 4000 个 Unicode 字符。评论创建后成为主题；回复、解决、重开和重新关联都追加事件，形成按序号排列的消息流。

### 5.2 原网页交互保护

- 评论运行时不代理全页 `click/pointer/touch/wheel` 事件。
- 可视标记使用 `pointer-events: none`，并且退出评论模式后移除标记、监听器、观察器和未完成请求。
- 地图、图表、播放器、编辑器等模块使用 `data-hs-comment-interaction="preserve"`；容器只识别外层模块，不遍历或读取内部运行时 DOM。
- 交互模块不覆盖透明遮罩，评论从侧栏发起；拖拽、缩放、Marker、信息窗和原按钮继续由页面自身处理。
- 托管页面作为 iframe 子模块加载时不重复注入菜单。

## 6. 页面更新与定位

页面应遵循 [HTML 评论结构标准](../../skills/home-server-web-share/references/html-comment-contract.md)。核心标记为：

- 根节点 `html[data-hs-comment-schema="1"][data-hs-page-id]`。
- 正文范围 `data-hs-comment-root`。
- 稳定目标 `data-hs-comment-id`、`data-hs-comment-kind`、`data-hs-comment-label`。
- 交互保护 `data-hs-comment-interaction="preserve"`。
- 排除区域 `data-hs-comment-ignore`。

重新发布后的定位顺序：

1. 用稳定 page ID 确认逻辑页面；没有 page ID 时使用项目相对路径。
2. 有 target ID 时在目标范围内匹配原文；模块和图片直接匹配唯一 target ID。
3. 文字原文重复时，使用保存的前后文消歧；仍不唯一时不猜第一个结果。
4. 当前页面找不到原文时，将未解决主题显示在页尾，并提示“原文无法定位”。
5. 按路径标识的其他页面明确返回 404 时，在入口页页尾显示“页面已删除”；稳定 page ID 的旧路径 404 可能是改名或删除，保守提示“原页面路径不可访问，可能已改名或删除”；网络失败不能判定删除。
6. 已解决主题仍保留历史，可从历史中重新打开。

语义对象未变化时必须沿用 ID；内容已替换为其他对象时必须分配新 ID。重复 ID 或未知 schema 版本不阻止页面浏览，但评论能力保守降级。

## 7. 应用与 Skill

`home-server-web-share` skill 提供：

- 按状态或 `request_id` 查询评论。
- 查看主题及完整事件分页。
- 创建整页、文字、图片或模块评论。
- 回复、解决、重开和重新关联。
- 生成/修改 HTML 时遵循稳定锚点和交互保护标准。

每个写操作必须带调用方生成的 `request_id`。同一身份、项目和 `request_id` 的相同请求返回原结果；参数不同返回冲突。连接中断后先按 `request_id` 查询，不自动重试未知结果。

## 8. 验收标准

### 8.1 访问与权限

- 公开页面匿名可浏览，只显示导航与未登录状态，不出现评论按钮、评论数据或评论请求。
- 私有/成员页面对无权用户返回 404；有权用户正常浏览。
- 浏览器与应用 scope 权限按第 3 节矩阵执行；禁用/过期/撤销身份不能继续写入。

### 8.2 评论生命周期

- 整页、文字、图片、模块评论可创建并持久化。
- 用户和 AK/SK 应用的回复都显示身份快照；应用代写同时保留用户 ID 与应用 ID。
- 评论、回复、解决、重开和重新关联事件记录调用方实际查看的 release；历史版本必须属于当前项目。
- 解决后可回复、可重新打开；状态操作使用 revision 防止覆盖并发更新。
- 同一 `request_id` 的并发重复请求只产生一个事件/主题。

### 8.3 更新与兼容

- 保留稳定 ID 的新版页面继续显示评论。
- 原文消失、页面删除时，未解决评论按第 6 节显示在页尾。
- 旧项目升级后保持原样，切换 `raw` 不删除评论。
- 页面按钮、表单和交互模块在浏览/评论模式均可使用；地图模块不被容器重建或遮挡。

### 8.4 界面与工程质量

- 桌面和 320px 窄屏菜单、侧栏可用，长项目名不遮挡评论面板。
- 页面切换、退出登录、身份变化会清理旧评论数据、草稿和迟到响应。
- 后端迁移、构建、API 生命周期、前端测试和真实 Chromium 测试全部通过。
- Pi 使用专用数据库、存储、配置、HTTPS 入口和回环端口完成真实服务验收：私有 404、匿名隐藏、默认浏览、原交互、文字/模块评论、应用回复、解决/重开、跨版本定位、失锚页尾与 Skill 命令链均通过。

## 9. 当前边界

- 首版不支持地图内部 POI、经纬度或屏幕坐标评论；评论绑定地图模块整体。
- 未标记旧 HTML 支持整页评论和唯一文字引用，不猜测 canvas、iframe 或自定义组件内部结构。
- 项目共享浏览器同源；适用于本人和受信任维护者上传的 HTML，不提供不可信 JavaScript 的项目间隔离。
- 页面自带 CSP 必须允许同源容器脚本；无法调整的 nonce/hash 限定页面使用原始页面模式。
- 评论附件、@提醒、实时推送、多人在线光标不在当前数据模型中。
