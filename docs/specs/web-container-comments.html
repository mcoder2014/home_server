网页托管增强容器与评论能力

让托管服务作为统一主容器提供导航、登录状态和可追踪评论，同时把原网页的按钮、表单、地图、图表与播放器交互完整保留下来。

默认浏览匿名隐藏评论稳定 HTML 锚点AK/SK 评论跨版本定位

核心判断

值得实现。网页评审所需的账号、权限、存储和升级属于宿主能力，不应由每个 HTML 重复实现。

主题保存当前与原始定位，事件保存不可变历史。两张表即可支持回复、解决、重开与重新关联。

兼容原则

新项目默认使用增强容器；已有项目迁移后保持 raw。增强模式只变换 HTML 响应，不修改已发布文件、下载内容或非 HTML 资源。

地图等交互模块只从侧栏选择，容器不增加透明遮罩、不代理手势，也不重建第三方实例。

系统架构

访问与权限矩阵

身份页面评论数据写操作
未登录仅公开项目；其他返回真实 404不加载、不显示入口禁止
已登录可见用户按 owner/members/authenticated/public进入评论模式后可读创建、回复；自己主题可解决/重开/重新关联
项目所有者自己的项目可读；停用后仍可查历史可管理项目内任意主题
AK/SK 应用继承所属用户 ACLweb-comments:readweb-comments:write，遵循所属用户规则

托管页只取得评论专用 CSRF 摘要，不能取得账号级 CSRF Token。web-projects:write 不自动包含评论权限。

固定菜单与浏览状态

  • 显示项目名称、登录显示名或“未登录”。
  • 提供系统主页 / 与网页托管 /web-share。
  • 已登录且有权时才显示评论按钮。
  • 刷新、新标签、页面路由或账号变化后默认浏览。
  • 浏览状态不加载评论正文、不监听文字选区。

可评论对象

  • 整页：稳定 page ID，旧页面回退到项目相对路径。
  • 文字：目标 ID + 原文 + 前后文。
  • 图片：从侧栏选择唯一 target ID。
  • 模块：从侧栏选择外层 target ID，保护内部交互。

建议的 HTML 标准

当前 schema 为 1。页面和模块 ID 使用 1～96 位小写语义标识：^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$。同一 page ID 下 target ID 唯一。

<html data-hs-comment-schema="1" data-hs-page-id="trip-guide">
  <main data-hs-comment-root>
    <section data-hs-comment-id="day-one-summary"
             data-hs-comment-kind="text">
      上午参观博物馆，下午沿河步行。
    </section>
    <figure data-hs-comment-id="route-map"
            data-hs-comment-kind="module"
            data-hs-comment-label="路线地图"
            data-hs-comment-interaction="preserve">
      <div id="map-container"></div>
    </figure>
    <form data-hs-comment-ignore>...</form>
  </main>
</html>
属性用途
data-hs-comment-root限定可定位正文区域。
data-hs-comment-id/kind/label声明稳定对象及 text/image/module 类型和侧栏名称。
data-hs-comment-interaction="preserve"把整棵子树视为业务交互保护区，只允许关联外层模块。
data-hs-comment-ignore排除表单、敏感内容和不应参与评论的子树，优先级最高。

地图和组件保护

评论标记不接收指针事件；地图、图表、播放器和编辑器没有透明覆盖层。用户从侧栏选择“路线地图”，评论绑定外层模块。

容器不调用 destroy()、不重建实例、不改写交互开关，也不抓取运行时 DOM。拖拽、滚轮/双指缩放、Marker、信息窗和工具条仍由原页面负责。

重新发布后的定位

  1. 优先用 page ID；没有时用相对路径。
  2. 在唯一 target ID 内核对原文。
  3. 重复原文使用前后文消歧。
  4. 仍不唯一时不猜测，放入页尾。
  5. 路径型页面明确 404 才标记删除；稳定 page ID 的旧路径不可访问时保守提示“可能已改名或删除”。

主题、事件与并发

结构保存内容关键约束
web_comment_thread当前/原始 release、page、anchor，状态、revision、作者快照列表快速读取；状态为 open/resolved
web_comment_eventcomment、reply、resolve、reopen、reanchor 完整历史(thread_id, sequence) 唯一

回复也递增 revision。解决、重开和重新关联必须携带最新 If-Match，避免覆盖未读回复。事件的 source_release_id 记录调用方实际查看的页面版本。每次写操作带 request_id；同一身份与项目的相同请求返回原结果，参数变化返回冲突。

API 与 Skill 能力

能力接口/命令
上下文GET /api/web-share/{id}/view-context
主题列表/详情GET .../comment-threads、GET .../{thread_id}
事件历史GET .../{thread_id}/events，自动读取分页
创建/回复comment-create、comment-reply
状态与位置comment-resolve、comment-reopen、comment-reanchor

正文从 UTF-8 普通文件读取，最多 4000 个 Unicode 字符。写结果未知时按原 request_id 查询，确认未执行后才能以完全相同参数重试。

  • 前端 60 项回归与生产构建。
  • 真实 Chromium：匿名、默认浏览、文字/图片/模块、窄屏、iframe、失锚。
  • Skill：分页、正文文件、幂等读回和 revision。
  • Pi 专用数据库、存储、配置和端口的隔离部署。

当前边界

首版不支持地图内部 POI、经纬度或屏幕坐标评论；未标记旧 HTML 不猜测 canvas、iframe 或自定义组件内部结构。评论附件、@提醒、实时推送和多人在线光标不在当前数据模型中。

所有托管项目共享浏览器源，适用于本人和受信任维护者上传的代码。评论专用 CSRF 缩小了托管脚本可调用的平台写接口范围，但不构成恶意同源 JavaScript 的隔离沙箱。页面自带 CSP 时需允许同源容器脚本；无法调整的 nonce/hash 限定页面使用原始页面模式。
