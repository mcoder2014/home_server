## 会话 SQL

使用 `EXPLAIN`、`ANALYZE FORMAT=JSON` 与七次数据库查询耗时中位数。数据均保留 `is_expired=0`，过期与有效记录具有合法的不同 TTL，旧认证版本记录尚未自然到期。42 项查询结果对照与原集合完全一致。耗时仅为共享 Pi 的数据库查询耗时，不含 HTTP／隧道延迟。

| 合成数据 | 最终查询 | 实际扫描会话行数 | SQL 中位数 |
| --- | --- | ---: | ---: |
| 单用户 10,000 历史：9,995 过期＋5 有效 | 列表，排除当前会话 | 4 | 0.76 ms |
| 单用户 10,000 历史：9,900 过期＋100 有效 | 列表，排除当前会话 | 99 | 1.41 ms |
| 单用户：9,000 过期＋995 旧版本未到期＋5 有效 | 列表／数量／签发名额检查 | 4／5／5 | 0.75／0.73／0.71 ms |
| 100 用户：9,000 过期＋500 旧版本未到期＋500 有效 | 一次批量 OR 聚合 | 500 | 7.45 ms |
| 单用户遗留 10,000 条全部有效 | 首列表／游标下一页 | 22／21 | 0.57／1.10 ms |

有效总数不超过 100 时，列表使用 `USE INDEX (idx_login_token_effective_range)`，按固定用户／版本与到期时间筛选后排序。仅新增索引并让优化器自然选择不能稳定排除过期扫描：同为 100 有效／9,900 过期时，排序索引曾扫描 9,922 行。大于 100 的合法存量保留自然分页索引选择，避免排序全部有效记录；总数仍准确返回 10,000，签发名额检查仍至多读取网站上限条数。管理员聚合使用同快照用户／版本常量，但保留自然索引选择。

## 上线边界

验证完成不等于生产启用。上线先按 [增量升级说明](../../account-center-operations.md) 应用 11 阶段结构，再部署匹配后端、代理与前端，并启用受限维护任务。更旧后端不识别已发布的新策略字段，回滚需准备兼容策略。正式规模和 DDL 维护窗口由上线预检确定。
