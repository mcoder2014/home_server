# WebDAV Basic 密码校验缓存

## 目标与现状

macOS Finder 浏览 WebDAV 目录时会连续读取目录属性、`._*` 和 `.DS_Store` 等元数据。现有 Basic 认证在每个请求上读取账号并执行 bcrypt。现场小请求耗时约 294–342 ms，同机合成密码的 cost 12 bcrypt 校验约 281 ms，重复计算显著放大了目录浏览等待。

目标是复用已经成功的密码计算结果，同时保留既有认证协议、失败预算、账号状态和方法权限的检查顺序。

## 方案选择

| 方案 | 收益与代价 | 选择 |
| --- | --- | --- |
| WebDAV 专用进程内成功校验缓存 | Finder 无需更换协议；首次和过期请求执行 bcrypt，后续请求复用计算结果；无需 Redis 或数据库迁移 | 采用 |
| 降低账号 bcrypt 成本 | 会改变密码保护策略，且已有哈希仍保留原成本 | 不采用 |
| 改用 Bearer 会话或独立客户端 | 能减少重复密码计算，但改变 Finder 现有接入方式 | 不采用 |

## 数据与边界

| 项目 | 规则 |
| --- | --- |
| 适用范围 | 仅 `PasswordBudgetWebDAV`；网站登录、管理员密码确认和改密不复用结果 |
| 缓存内容 | HMAC-SHA256 摘要与过期时间；不保存明文密码、完整账号对象或权限快照 |
| 摘要输入 | 账号键、当前 bcrypt 哈希、此次提交的完整密码；字段之间使用零字节分隔 |
| HMAC 密钥 | 每进程通过系统随机源生成 32 字节；初始化失败显式终止启动 |
| 有效期 | 成功 bcrypt 校验完成后 5 分钟，命中不延长 |
| 容量 | 最多 1024 条；满时回收过期条目，仍满则完成正常认证但不新增缓存 |
| 失败请求 | 不写入成功缓存，沿用原失败计数和限流响应 |
| 生命周期 | 仅内存保存，重启后清空；不引入后台线程、外部依赖或部署配置 |

## 请求流程与兼容性

![WebDAV Basic 成功密码校验缓存流程](flow.svg)

1. 保留 HTTPS、认证来源和 Basic 格式检查。
2. 按原调用链读取当前账号及密码哈希。
3. 执行原有账号和来源 IP 失败预算检查；即使凭据曾经命中成功缓存，预算耗尽仍拒绝。
4. WebDAV 请求按当前输入查询成功缓存。有效命中只跳过 bcrypt；未命中执行原密码校验，成功后按容量规则记录。
5. 继续检查当前账号状态、临时密码期限、模块开关及请求方法权限，再进入文件操作。

改密产生的新哈希使旧缓存键失配。封禁、撤销 WebDAV 权限和关闭模块仍由每次请求的当前状态检查拒绝。账号查询或权限读取失败继续返回原错误，缓存不能替代这些读取。并发首次请求允许重复进行 bcrypt，各请求按原规则完成认证；不同用户不会因全局锁等待另一个用户的 bcrypt。

## 验收标准

- 正确凭据复用成功结果；错误密码、不同账号和已变更哈希不能错误命中。
- 网站及已登录密码确认不使用 WebDAV 缓存。
- 命中不续期；过期后重新校验；成功和失败流量均不能使条目超过 1024。
- 已热缓存仍服从失败预算；现有失败响应及三个预算的隔离语义保持一致。
- 在隔离数据上验证热缓存后的改密、封禁、撤权及模块关闭立即生效。
- 执行并发与竞态检查，并用相同 Go 基准比较 cost 12 普通校验和 WebDAV 热缓存。

## 上线与回滚

功能、竞态、构建和密码校验性能结果见[验证记录](verification.md)。

仅需发布后端二进制。无需改数据库、密码哈希、Nginx 或客户端地址。回滚旧二进制恢复逐请求 bcrypt，账号和文件数据保持兼容。实际 Finder 目录切换耗时需在部署后验收，函数基准不等同于完整目录浏览性能。
